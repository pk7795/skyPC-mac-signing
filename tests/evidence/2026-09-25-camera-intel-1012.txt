SkyPC camera enumeration and Intel macOS 10.12 follow-up
Date: 2026-09-25

Scope
- Preserve Apple Silicon minimum macOS 11.0.
- Set Intel minimum macOS 10.12 and make the app self-contained for Swift
  back-deployment overlays.
- Distinguish camera permission/backend failures from a real empty device list.

Source diagnosis
- The prior hardware::enumerate_cameras converted every camera backend error
  into Vec::default(), so the UI could only show Off.
- The pinned cameras package exposes Error::PermissionDenied separately.
- The production Info.plist already has NSCameraUsageDescription.
- system_profiler SPCameraDataType -json returned no camera on the current Mac.
  Microphone discovery uses a separate backend and is not evidence of camera
  availability.
- No TCC database was changed or reset.

Implemented contracts
- build_mac_artifact.sh passes deployment target 11.0 for arm64 and 10.12 for
  x86_64, and writes the same value to each app Info.plist.
- The Intel executable prefers @executable_path/../Frameworks. When it links a
  Swift overlay, swift-stdlib-tool copies the needed dylibs into the app before
  ad-hoc signing.
- release_skypc.sh --minimum-os writes the production plist, permits only the
  reviewed app-local and Apple system Swift RPATHs, requires app-local Swift
  below macOS 11, records dylib hashes and signs nested dylibs before the app.
- release_skypc_v3.sh validates and forwards 11.0 for arm64 and 10.12 for Intel.
- Camera enumeration is asynchronous and reports localized no-device,
  permission-denied and backend-error messages.
