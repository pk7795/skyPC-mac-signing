SkyPC DMG background recheck — 2026-09-22

Result
======

CONFIRMED DEFECT in the already signed/notarized 0.9.26 build 3 and 0.9.27
build 4 images: their packaged background.jpg is 1800x702 pixels at 72 DPI.
Native AppKit therefore reads a logical size of 1800x702 points while the Finder
window is 900x351 points. The existing alias resolves to the packaged image, so
the issue is image density/scale rather than a missing alias target.

Fix
===

release_skypc.sh now converts the source artwork to lossless
.background/background.tiff, writes 144 DPI, and reads pixel/DPI values back
before continuing. dmg_layout.py performs the same logical-size check when
configuring the writable image and verifying the final read-only image. A
successful sips exit alone is no longer accepted as proof that the density was
stored.

Superseded conclusion
=====================

The later 0.9.27 build 5 visual check proved that logical TIFF size plus a
parseable alias did not prove Finder accepted the background. Finder did not
write a pBBk/pBB0 bookmark for the directly generated metadata and displayed a
plain dark background. Keep this report as density-fix evidence; use
2026-09-22-background-finder-fix.txt for the current Finder acceptance gate.
