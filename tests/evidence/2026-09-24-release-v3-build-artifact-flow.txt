SkyPC macOS release v3 build-artifact flow — 2026-09-24

Observed build boundary
=======================

skypc-app/README.md directs macOS builds through build_mac_artifact.sh. That
script compiles one target architecture, creates skyPC.app with the historical
bundle ID com.skypc.client, ad-hoc signs the app, and emits one of:

- skypc-app/dist/skyPC-macOS-AppleSilicon.dmg
- skypc-app/dist/skyPC-macOS-Intel.dmg

Those images are useful build/test artifacts. Their bundle identity, ad-hoc
signature, metadata and DMG layout do not satisfy the existing production
Developer ID contract for com.sub2s.skypc.

V3 design
=========

Mac-signing/release_skypc_v3.sh accepts one explicit architecture and package
build. It performs this sequence:

1. Read the version from skypc-app/Cargo.toml.
2. Run build_mac_artifact.sh with Cargo --locked enabled.
3. Require both target/<triple>/release/skypc and the expected build DMG.
4. Mount only that DMG read-only and parse its returned device/mount plist.
5. Require com.skypc.client and the Cargo version in its source app.
6. Require its embedded executable to match the target binary byte-for-byte.
7. Detach only the returned device.
8. Delegate the target binary to release_skypc_v2.sh, which rejects the paused
   SMAppService marker and uses the common Developer ID release engine.
9. Pass the source DMG through release_skypc.sh --source-artifact so its hash is
   recorded in release-evidence.txt.

The preferred prebuilt mode is
`release_skypc_v3.sh --binary ../skypc-app/target/release/skypc --build N`.
`build_mac_artifact.sh --binary` detects the binary architecture and skips
Cargo. V3 disables ad-hoc signing only for this intermediate provenance image,
because ad-hoc signing mutates the copied Mach-O and would make byte comparison
with the supplied unsigned binary impossible. Developer ID signing remains in
the production release engine.

The script rejects `all`, caller-supplied versions, missing/duplicate build
numbers and LaunchAgent injection. Separate architecture runs keep output and
runtime evidence unambiguous. Cleanup reparses the attach plist after an
interrupted or partially failed attach so it can detach its own device.

All-output correction
=====================

The operator clarified that the canonical build entry point is
`./build_mac_artifact.sh all`; no separate native `cargo build -r` or v3 rebuild
should occur. V3 now accepts `--from-build all`, requires the two thin target
binaries and corresponding ad-hoc DMGs, checks both artifacts before either
production release starts, and then invokes the shared legacy signing pipeline
once per architecture. It does not invoke the build script. Because ad-hoc
signing changes the copied Mach-O bytes, the from-build boundary validates each
DMG's bundle ID, Cargo version, exact thin architecture, valid ad-hoc bundle
signature and artifact freshness relative to its target binary; release evidence
records both target and source-artifact hashes. A controlled two-architecture
prepare-only test passes and proves the build script is not invoked.

The operator's first real all-output preflight accepted ARM, then correctly
stopped Intel because it linked `@rpath/libswiftCoreMedia.dylib` without any
LC_RPATH and declared macOS 10.12 while the app bundle requires 11.0. The build
script now exports MACOSX_DEPLOYMENT_TARGET=11.0, and the x86_64 Cargo target
adds only `/usr/lib/swift` as its runtime RPATH. The release dependency gate
allows `@rpath/libswift*.dylib` only when that is the executable's sole RPATH;
an unsafe app-local RPATH remains rejected. Rebuilding Intel removed the overlay
dependency, produced LC_BUILD_VERSION minos 11.0 and retained only the reviewed
system RPATH.
