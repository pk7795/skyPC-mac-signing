SkyPC Hardened Runtime media entitlement incident
Date: 2026-09-25

Observed behavior
- The unsigned/ad-hoc app requested Camera and Microphone access. After the
  operator approved access, the Camera dropdown listed the built-in FaceTime
  camera and an iPhone continuity camera.
- The installed Developer ID build 13 did not request Camera access. Its Camera
  dropdown stayed at Off and the typed permission-denied UI advised enabling
  SkyPC under System Settings > Privacy & Security > Camera.
- Microphone enumeration returned devices in the signed app. Enumeration alone
  is not evidence that microphone capture authorization or capture succeeds.

Build 13 diagnosis
- App: releases/SkyPC-0.9.38-13-20260924T172232Z.WuWCvG/build/SkyPC.app
- Identity: com.sub2s.skypc, version 0.9.38, build 13.
- Designated requirement: Apple Developer ID, team P4F9DNFZ68.
- Info.plist contains NSCameraUsageDescription and
  NSMicrophoneUsageDescription.
- `codesign -d --entitlements :- SkyPC.app` succeeded but wrote zero entitlement
  bytes. The Hardened Runtime signature therefore carried neither
  com.apple.security.device.camera nor
  com.apple.security.device.audio-input.
- The unsigned/ad-hoc build and production build use different signing
  identities, and the historical build artifact uses com.skypc.client while
  production uses com.sub2s.skypc. Their TCC records are not interchangeable.
- The pinned macOS camera backend requests access only for NotDetermined; a
  remembered Denied/Restricted state returns PermissionDenied without a new
  prompt. No TCC database was read, changed, or reset during this diagnosis.

Root cause and correction
- Build 13 enabled Hardened Runtime without the media resource entitlements.
  Usage-description strings control prompt text but do not replace the resource
  entitlements required by this production signature.
- Added template/SkyPC.entitlements with only camera and audio-input set true.
- release_skypc.sh now validates both values before preparation, records the
  entitlement file hash, signs the app with it, extracts the completed
  signature with `codesign -d --entitlements :-`, lints the resulting plist,
  and fails before runtime/notarization unless both signed values are true.
- The manual gate now explicitly rejects an Off-only Camera list and tells the
  operator to enable the production bundle in System Settings when macOS has
  retained a prior denial.
- The first extractor used `--entitlements -`. Real signing showed that current
  codesign emits a non-plist `[Dict]` representation for that argument. The
  corrected `:-` spelling emits an XML plist; the contract mock now enforces
  this exact argument.

- Produce a new monotonically numbered Developer ID/notarized build with the

- Quit the old app, install/open the corrected app, then verify Camera and
