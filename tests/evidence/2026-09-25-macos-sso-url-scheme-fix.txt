SkyPC macOS Google SSO callback packaging fix — 2026-09-25

Observed behavior
-----------------
- Unsigned/ad-hoc build: Google completes authentication and returns to SkyPC.
- Developer ID build 14: Google reports success in the browser, but SkyPC does
  not receive the callback.

Source call path
----------------
- Message::AuthGoogleLogin requests `/v1/auth/oidc/start?target=desktop` and
  opens the returned browser URL.
- The callback contract is `skypc://oidc-complete?code=...`.
- macOS `application:openURLs:` forwards the URL to Message::AuthOidcCallback.
- `oidc_callback_code` validates scheme `skypc`, host `oidc-complete`, and one
  non-empty `code`, then `/v1/auth/oidc/exchange` completes login.

Root cause
----------
- skypc-app/build_mac_artifact.sh already writes CFBundleURLTypes containing:
  - CFBundleTypeRole=Viewer
  - CFBundleURLName=com.skypc.client.oidc
  - CFBundleURLSchemes[0]=skypc
- Mac-signing/template/Info.plist did not contain CFBundleURLTypes. The v3
  production pipeline rebuilds the app bundle from this independent template,
  so it discarded the URL registration present in the unsigned build artifact.
- Signing and notarization succeeded because URL scheme registration is an app
  metadata/runtime contract, not a notarization acceptance condition.

Fix
---
- Added the production URL type with role Viewer, name
  com.sub2s.skypc.oidc, and scheme skypc.
- release_skypc.sh validates all three values before creating output and again
  after constructing the release bundle.
- release_skypc_v3.sh rejects a source build artifact without the skypc scheme.
- The manual runtime prompt explicitly requires a Google SSO browser callback.
- No SSO source, backend, callback parser, UI, toast, or locale behavior changed.
